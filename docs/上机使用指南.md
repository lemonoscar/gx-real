# gx-real Flat / Rough 真机上机使用指南

本文是当前 `Go2 + X5/ARX5 + Jetson` 生产入口的唯一操作指南。当前架构不允许在行走策略运行中使用 SpaceMouse 改变 X5 姿态。

## 0. 当前放行状态

截至 2026-07-16：

- Flat manifest：`UNRELEASED`；
- Rough manifest：`UNRELEASED`；
- Rough perception contract：`UNVERIFIED`，LiDAR、外参、self-filter 和 mapping 配置仍为 `UNSET`；
- Go2 最终腿部安全合同和目标硬件低能量证据尚未完成。

因此当前代码会在创建真实控制节点前 fail-closed。不要修改 `RELEASED`、`VERIFIED` 或哈希字段来绕过门禁。

## 1. 两个互斥部署类

| 部署类 | 腿策略 | 高度观测 | X5 owner | 生产入口 |
| --- | --- | --- | --- | --- |
| Flat | `policies/policy.onnx` | `[66:253]` 精确 187 个零，不创建 provider | `x5_fixed_hold` | `run_leg12_flat_real.sh` |
| Rough | `policies/rough/current/policy.onnx` | `GridMap/elevation` -> stamped 17×11，失效即撤销运动许可 | `x5_fixed_hold` | `run_leg12_rough_real.sh` |

运行中不能热切换。切换类别必须停止两个 writer、释放锁、重新执行对应 preflight。

旧入口 `scripts/run_leg12_real.sh` 因策略类别不明确而固定退出。生产 WBC 也会拒绝 `external_spacemouse`、`fixed_initial` arm observation 和缺失的 arm freshness gate。

## 2. 不变量

- 同时只能有一个 Go2 LowCmd writer 和一个 X5 CAN writer。
- WBC 只写 Go2；X5 fixed-hold 节点只写 X5。
- X5 目标固定为部署配置中的训练姿态，当前两类均为 `[0.0, 0.3, 0.5, 0.0, 0.0, 0.0]`，gripper 为 `0.0`。
- `/arm/state` 与 `/arm/target_state` 必须持续 fresh、同一 `x5_fixed_hold` producer，并满足姿态/跟踪误差合同。
- Rough 生产只允许 `grid_map_msgs/msg/GridMap` 的 `elevation` layer；Unitree HeightMap/raw pointcloud 只可诊断，也不允许 zero/last-valid fallback 进入 actor。
- L1、writer 冲突、manifest/哈希不一致、arm fault、感知 fault 或 watchdog fault 均不得自动恢复运动。

## 3. 一次性环境准备

在 Jetson 上使用系统 Python，不使用 Conda：

```bash
conda deactivate 2>/dev/null || true
cd ~/gx-real
uname -m
/usr/bin/python3 --version
/usr/bin/python3 -c "import onnxruntime; print(onnxruntime.__version__)"
```

`uname -m` 必须是 `aarch64`。构建 Unitree/robot_state 消息和 ARX5 Python 接口的细节见仓库 README；每次运行的 mode-specific preflight 默认也会执行所需构建。

Rough 的 perception workspace 必须提供 `grid_map_msgs` 和 mapping 节点；若它们
不在 base ROS install 中，在 source gx-real 前显式指定其安装环境：

```bash
export GX_REAL_PERCEPTION_SETUP=/absolute/path/to/perception_ws/install/setup.bash
source scripts/setup_env.sh
/usr/bin/python3 -c "from grid_map_msgs.msg import GridMap; print(GridMap)"
```

不要把开发机上的 phase workspace 路径硬编码到 Jetson；最终 workspace、commit
和 mapping 配置哈希必须进入 perception contract。

## 4. 发布包离线验证

Flat：

```bash
/usr/bin/python3 scripts/height_scan/check_policy_height_scan_contract.py \
  --policy-kind flat \
  --policy policies/policy.onnx \
  --env-yaml policies/env.yaml
```

Rough：

```bash
/usr/bin/python3 scripts/height_scan/check_policy_height_scan_contract.py \
  --policy-kind rough \
  --policy policies/rough/current/policy.onnx \
  --env-yaml policies/rough/current/env.yaml \

```

Rough 检查必须同时通过：260D/12D shape、live env term、17×11 网格、10 cm 台阶敏感性、Torch/ONNX reference parity 和 CPU timing。

## 5. 每次上机前置检查

Flat：

```bash
cd ~/gx-real
scripts/prepare_flat_run.sh \
  --network-iface eth0 \
  --can-if can0 \
  --check-joystick-motion
```

Rough：

```bash
cd ~/gx-real
scripts/prepare_rough_run.sh \
  --network-iface eth0 \
  --can-if can0 \
  --check-joystick-motion
```

两者都会检查 Jetson 架构、系统 Python、ROS2/CycloneDDS、构建产物、CAN、Go2 topic、writer 冲突并关闭 sport mode。Rough 额外要求以下链路能持续产出消息：

```text
/lidar/points_deskewed
/lidar/imu_raw
/terrain/elevation_map
/localization/pose
```

preflight 默认不要求 SpaceMouse。`--spacemouse` 只用于旧输入设备诊断，不属于当前生产启动条件。

在仍保持 actuator 禁能时，可单独显示送入 app/device 侧的 187D GridMap
诊断（该命令不创建 Go2/X5 writer）：

```bash
/usr/bin/python3 real-wbc/scripts/run_height_scan_monitor.py \
  --source grid_map \
  --topic /terrain/elevation_map \
  --pose-topic /localization/pose \
  --map-layer elevation \
  --contract policies/rough/current/height_scan_contract.yaml \
  --max-critical-sentinel-cells 0
```

Unitree `/utlidar/height_map_array` 只能另开 diagnostic/A-B 进程读取，不能传给
rough 生产入口。后端取舍证据见
[`lidar_height_backend_decision_2026-07-16.md`](lidar_height_backend_decision_2026-07-16.md)。

## 6. 受控启动顺序

本节只在对应 manifest、感知合同和腿部安全合同均已按真实证据发布后执行。当前仓库状态不满足该条件。

### 6.1 终端 A：启动匹配的 X5 fixed-hold owner

Flat：

```bash
cd ~/gx-real
export GX_REAL_NETWORK_IFACE=eth0
source scripts/setup_env.sh
scripts/run_x5_fixed_hold_flat.sh \
  --model X5 \
  --can-interface can0 \
  --safety-topic /safety/estop
```

Rough 只把入口换成：

```bash
scripts/run_x5_fixed_hold_rough.sh \
  --model X5 \
  --can-interface can0 \
  --safety-topic /safety/estop
```

节点启动后保持 STANDBY/damping，并发布 arm state；它不会自行使能固定姿态。

### 6.2 终端 B：启动匹配的腿部部署类

Flat：

```bash
cd ~/gx-real
export GX_REAL_NETWORK_IFACE=eth0
source scripts/setup_env.sh
scripts/run_leg12_flat_real.sh \
  --device cpu \
  --pose_estimator none \
  --standup-mode internal \
  --base-command-source wireless_joystick \
  --joy-max-vx 0.50 \
  --joy-max-vy 0.0 \
  --joy-max-yaw 0.0 \
  --arm-control-owner external_fixed_hold \
  --require-arm-state-for-rl \
  --leg-kp 200 \
  --leg-kd 10
```

Rough 使用相同参数，但入口必须是：

```bash
cd ~/gx-real
export GX_REAL_NETWORK_IFACE=eth0
source scripts/setup_env.sh
scripts/run_leg12_rough_real.sh \
  --device cpu \
  --pose_estimator none \
  --standup-mode internal \
  --base-command-source wireless_joystick \
  --joy-max-vx 0.50 \
  --joy-max-vy 0.0 \
  --joy-max-yaw 0.0 \
  --arm-control-owner external_fixed_hold \
  --require-arm-state-for-rl \
  --leg-kp 200 \
  --leg-kd 10
```

不得手工传入另一类 policy/manifest，也不要覆盖 `--arm_pose`。入口会从签名部署配置读取策略、manifest 和训练 arm pose。

### 6.3 终端 C：显式使能 fixed-hold

确认终端 A/B 均无 fault、WBC safety heartbeat 正常、X5 当前关节离训练姿态不超过启动阈值后：

```bash
source scripts/setup_env.sh
ros2 topic pub --once /arm/fixed_hold/enable std_msgs/msg/Bool "{data: true}"
```

使能后必须看到 X5 target source 为 `x5_fixed_hold`、state/target fresh，并等待跟踪误差进入合同范围。任何 feedback、lease 或 tracking fault 都会锁存并切回 damping。

## 7. 手柄流程

- `R1`：开始受控起身；
- `L2`：在所有门通过后进入 policy alignment/rollout；
- `R2`：正常停止 policy，进入被动停止路径；
- `L1`：软件急停，锁存 ESTOP 并通知 X5 damping；
- 摇杆：仅生成底盘速度；不控制 X5。

首次硬件试验必须从架空/shadow、零速度和最短限时开始。没有独立复核和现场保护人员时不要进行低层输出测试。

## 8. 正常停止顺序

1. 松开手柄并按 `R2`；
2. 明确关闭 fixed-hold：

   ```bash
   ros2 topic pub --once /arm/fixed_hold/enable std_msgs/msg/Bool "{data: false}"
   ```

3. 确认 X5 已进入 damping；
4. Ctrl-C 终端 B；
5. Ctrl-C 终端 A；
6. 检查没有残留 writer：

   ```bash
   pgrep -af "run_wbc|run_leg12|run_x5_fixed_hold|run_spacemouse_arm|arx5"
   ```

异常时直接按 L1/物理急停，不能为了保存日志延迟停机。

## 9. Rough motion-permit 门

Rough 每帧至少验证：

- GridMap header stamp 有效且 age 不超过合同；
- message type 必须为 `grid_map_msgs/msg/GridMap`，且存在唯一 `elevation` layer；
- MultiArray 必须为 GridMapRosConverter 列主序，并应用 outer/inner circular start index；
- pose/map stamp skew 不超过 30 ms；
- map 与 pose frame 一致；
- scan shape 为 187，全部 finite；
- 全局和关键落足区 coverage 达标；
- critical sentinel 数不超限；
- 连续 5 帧有效后才允许运动；
- 任一无效/超时会把连续帧计数清零，恢复后的第一帧不能立即重新放行。

当前 mapping、自滤波、外参和硬件延迟证据仍未完成，因此 perception contract 保持 `UNVERIFIED`。

## 10. 发布 manifest 的可实现流程

manifest 不能声称“自己的 commit hash”，因为修改该字段会改变 commit。当前校验采用两次提交：

1. 提交所有代码、模型、合同和证据，得到 source commit；
2. 只修改一个目标 manifest：填入 source commit、真实版本/库哈希和 `RELEASED`；
3. 创建 manifest-only release commit；
4. 运行时要求 release commit 的父提交正好是 manifest 中的 source commit，且两者之间只改了该 manifest；
5. 工作树仍必须干净，所有发布资产哈希仍逐项验证。

若 release commit 同时改了代码、模型或第二个 manifest，启动会拒绝。

## 11. 当前仍需真实硬件/记录提供的证据

- LiDAR 型号、固件、刚性安装和 6DoF 外参；
- self-filter、elevation mapper 实现/配置哈希及 rosbag 回放；
- 平地、10 cm 台阶、左右/yaw、遮挡的仿真-实测 parity；
- map/pose rate、p95/p99 age/skew、coverage 和 CPU/GPU 占用；
- X5 CAN 丢失后的可靠 freshness 证据；
- Go2 关节限制、PD、电流/温度边界和最终指令安全合同；
- 架空 shadow、故障注入、零速站立、低速限时/限距结果与独立复核。

这些值不能从其他工程、当前默认值或一次成功运行推断。

## 12. 禁止事项

- 不要运行 `scripts/run_leg12_real.sh` 作为生产入口；
- 不要给生产 WBC 传 `external_spacemouse`、`wbc` 或 `fixed_initial`；
- 不要同时运行 fixed-hold、SpaceMouse arm writer、ARX 示例或 legacy writer；
- 不要在非 dry-run 下使用 `--allow-missing-can`；
- 不要让 Rough 在感知失败时退化为全零或 last-valid scan；
- 不要把 `UNRELEASED/UNVERIFIED/UNSET` 改字后直接上机；
- 不要在 `x86_64` 开发机执行真实部署命令。
