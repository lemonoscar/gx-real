# gx-real 真机上机使用指南

本文只覆盖当前 `main` 分支的最小真机流程：Flat 模型、固定 `0.3 m/s`、X5 固定训练姿态、internal FixStand，以及 L1 受控停机。

## 1. 当前固定基线

- 模型包：`go2_x5_dog_only_flat_2026-05-31_20-42-11_model_19000`。
- ONNX：`policies/policy.onnx`。
- 配套环境：`policies/env.yaml`。
- height scan：187 维全零 Flat observation。
- 动态 policy PD：12 个腿关节均为 `Kp=40, Kd=1`，直接从配套 `env.yaml` 读取。
- internal FixStand/趴下 PD：每条腿 `Kp=[60,80,80]`、`Kd=[5,4,4]`。
- 机械臂训练姿态：`[0, 0.3, 0.5, 0, 0, 0]`。
- 底盘命令：固定 `[0.3, 0, 0] m/s`，暂不建议使用无线摇杆速度。

不要再传 `--leg-kp` 或 `--leg-kd`。`40/1` 是策略训练 PD；FixStand 保留独立的 Unitree RL Lab PD，handover 会在 1.2 秒内平滑切换。

## 2. 每次上机前

确认 Go2 周围无人、地面平整、机械臂工作空间无障碍物，手柄在手边。然后在 Jetson 上执行：

```bash
conda deactivate 2>/dev/null || true
cd ~/gx-real
export GX_REAL_NETWORK_IFACE=eth0
source scripts/setup_env.sh
scripts/check_env.sh
```

`eth0` 必须替换成连接 Go2、具有 `192.168.123.x` 地址的真实网卡。

代码更新只能在工作树没有本地修改时执行：

```bash
git status --short
git pull --ff-only
```

如果 `git status` 有修改，不要用 `git reset --hard`；先确认这些修改是否仍需要保留。

## 3. 终端 A：启动机械臂固定姿态

```bash
conda deactivate 2>/dev/null || true
cd ~/gx-real
scripts/setup_arx_can.sh
scripts/run_arm_training_hold.sh
```

保持该终端运行。正常日志应包含：

```text
Using persistent X5 gripper calibration: width=0.088 open_readout=-5.07839
arm mode: fixed training-pose lock [0.000 0.300 0.500 0.000 0.000 0.000]
controlled home topic: /arm/home
safety estop topic: /safety/estop
```

没有看到 arm state/target 持续发布，或出现夹爪位置错误时，不要启动机器狗策略。

## 4. 终端 B：启动 Go2 固定速度

```bash
conda deactivate 2>/dev/null || true
cd ~/gx-real
export GX_REAL_NETWORK_IFACE=eth0
scripts/run_fixed_03_real.sh
```

入口会校验 `policy.onnx + env.yaml` 的 bundle 哈希并确认 MCF 已释放。看到 `Deploy node ready` 后：

1. 按一次 `R1`，执行 internal FixStand。
2. 等待机器狗完全站稳。
3. 按一次 `L2`，先零速度 handover，再平滑升到固定 `0.3 m/s`。

日志中 policy rollout 的 `lowcmd_kp` 应为 12 个 `40.000`，`lowcmd_kd` 应为 12 个 `1.000`。如果不是，停止运行并检查 `policies/env.yaml` 与 bundle，不要用命令行强行覆盖。

## 5. 当前手柄语义

- `R1`：Passive → internal FixStand。
- `L2`：FixStand → 零速度 policy handover → 固定 `0.3 m/s`。
- `Y`：只把底盘 command 平滑降为零，policy 继续保持站立。
- `R2`：立即停 policy，不作为正常下机流程。
- 第一次 `L1`：正常受控停机。
- L1 过程中再次按 `L1`：立即硬急停。

第一次 L1 后，R1、L2、R2、Y、A/B/X 和 D-pad 全部被门控屏蔽，避免停机过程中重新起身、恢复速度或改变机械臂命令。受控停机完成后也不允许在同一进程重新起身；下一次运行需要重启两个节点。

## 6. L1 受控停机顺序

第一次按下 L1 后严格按以下顺序执行：

```text
当前 policy 保持运行
  -> 1.5 s 内把 command 平滑降到 [0, 0, 0]
  -> 从实测腿关节姿态出发
  -> 2.4 s 内用 FixStand PD 平滑降到内部蹲伏/趴下姿态
  -> 保持 0.3 s
  -> 发布 /arm/home
  -> 狗继续保持趴下，X5 回到 [0, 0, 0, 0, 0, 0]
  -> 等待 1.0 s
  -> Go2 切换到 Kp=0, Kd=3 阻尼
```

正常过程中会依次看到：

```text
Controlled stop requested
Base command reached zero
Go2 is prone; holding FixStand PD while X5 returns to [0 0 0 0 0 0]
Controlled stop complete
```

在看到 `Controlled stop complete` 前不要 `Ctrl+C`，否则可能提前撤掉腿部 LowCmd。完成后可分别对两个终端按 `Ctrl+C` 退出。

以下情况不走慢速收尾，而是立即进入 `/safety/estop`：

- L1 受控停机过程中再次按 L1；
- LowState watchdog 超时；
- MCF/低层控制权冲突；
- policy、observation 或关节目标出现 NaN/Inf 等运行时故障。

硬急停只让 X5 进入阻尼，不会再命令它移动回零；这是为了避免真实故障时机械臂继续运动。正常机械臂回零只使用 `/arm/home`。

## 7. ARX SDK 夹爪零点校准的可能 bug

部分较新的 X5 夹爪电机安装方向与 ARX SDK 默认配置相反。典型现象是夹爪已经物理闭合，但 controller 启动时报：

```text
Gripper position error: got -0.08x but should be in 0~0.088 (m)
Emergency state entered. Please restart the program.
```

ARX SDK 的 `calibrate_gripper()` 会让操作者先完全闭合并设零，再完全打开，然后打印 fully-open 原始角度。可能的问题是：它打印的是原始读数，提示直接复制到 `gripper_open_readout`，但反向安装的电机需要使用负号。当前这台 X5 的实测 fully-open 绝对值为 `5.07839`，因此仓库在 controller 创建前永久覆盖为：

```text
gripper_width = 0.088
gripper_open_readout = -5.07839
```

该覆盖在 `real-wbc/modules/spacemouse_arm_node.py` 的 `apply_x5_gripper_calibration()` 中，只对 `--model X5` 生效。它不依赖修改 `~/.local` 下的二进制 `.so`，拉取仓库后即可持续生效。

检查实际加载的扩展与 SDK 原始默认值：

```bash
/usr/bin/python3 -c "import arx5_interface as a; c=a.RobotConfigFactory.get_instance().get_config('X5'); print('module=', a.__file__); print('width=', c.gripper_width); print('open_readout=', c.gripper_open_readout)"
```

这里仍可能显示 SDK 原始的正值 `5.03`，因为仓库覆盖发生在 SpaceMouse Arm Node 创建 controller 之前；最终以节点启动日志中的 `Using persistent X5 gripper calibration` 为准。

如果更换了夹爪、电机或 SDK，不能盲用 `-5.07839`。重新校准时必须确认：

1. 设置零点时夹爪确实完全闭合。
2. 读取宽度时夹爪确实完全打开。
3. 根据实际开合方向确认 `gripper_open_readout` 正负号。
4. 在不启动 Go2 的情况下先单独验证 X5，确认闭合约为 `0 m`、全开约为 `0.088 m`。

`/usr/bin/python3 -m pip show arx5-interface` 找不到包不代表扩展不存在；旧部署可能直接加载 `~/.local/lib/python3.8/site-packages/arx5_interface*.so`，以 `a.__file__` 输出为准。

## 8. 最小故障判断

- `MotionSwitcherClient::CheckMode failed`：先确认 Go2 网络接口正确，再单独运行 `scripts/disable_sports_mode_go2.sh eth0`。
- `Arm observation stale`：终端 A 未运行、已经退出，或 `/arm/state`、`/arm/target_state` 不再更新。
- policy `lowcmd_kp/kd` 不是 `40/1`：模型与 `env.yaml` 不匹配，停止并恢复绑定的 policy bundle。
- L1 后没有 `Base command reached zero`：保留终端日志；如果姿态正在失控，再按一次 L1 硬急停。
- L1 后狗已经趴下但机械臂不回零：检查终端 A 是否订阅 `/arm/home`，以及是否已经因更早的故障进入 estop。
