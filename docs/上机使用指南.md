# gx-real Flat / Rough 真机上机使用指南

本文是当前 `Go2 + X5/ARX5 + Jetson` 的生产操作手册。Rough 的标准顺序是：

```text
感知链稳定
  -> 启动 X5 fixed-hold owner（先 STANDBY/damping）
  -> Rough 真机入口检查并释放 MCF
  -> 启动 Go2 WBC（首次 LowState 后进入 Passive）
  -> WBC heartbeat 健康后使能 X5 固定目标
  -> arm/map 安全门通过
  -> 操作者 R1 执行 FixStand、L2 直接验姿并进入策略
```

X5 物理目标和 actor 输入都对应
`[0.0, 0.3, 0.5, 0.0, 0.0, 0.0]`，但两者是刻意分离的：真实
`/arm/state` 只用于 fixed-hold 安全检查，绝不会复制进网络观测。

## 1. 当前放行状态

当前仓库中的 Flat/Rough artifact manifest 为 `UNRELEASED`，Rough perception
contract 为 `UNVERIFIED`，部分目标硬件字段仍是 `UNSET`。代码会在创建真实 writer
前 fail-closed。因此本指南中的真实控制步骤只能在以下条件全部满足后执行：

- 目标 Jetson/Go2/X5 上完成构建和 preflight；
- Rough 按 [LiDAR 校准指南](lidar_calibration.md) 完成几何、self-filter、原生高度图和
  held-out rosbag 验收；
- Go2 最终腿命令安全合同和低能量硬件证据完成；
- perception contract、artifact manifest 由真实哈希发布并独立复核；
- 工作树干净，运行时 artifact 检查通过。

不要仅修改 `UNRELEASED`、`UNVERIFIED`、`UNSET` 字样或关闭校验来尝试上机。

## 2. 部署类型和不可破坏的不变量

| 部署类 | 策略 | 高度观测 `[66:253]` | 生产入口 |
| --- | --- | --- | --- |
| Flat | `policies/policy.onnx` | 精确 187 个零，不创建 provider | `run_leg12_flat_real.sh` |
| Rough | `policies/rough/current/policy.onnx` | live Unitree `HeightMap` | `run_leg12_rough_real.sh` |

运行中不得热切换 Flat/Rough。每次切换必须停止两个硬件 writer，再执行匹配的
preflight。旧入口 `scripts/run_leg12_real.sh` 会主动退出，因为没有部署类型的生产入口
是不安全的。

生产运行必须保持：

- 同时只有一个 Go2 LowCmd writer 和一个 X5 CAN writer；
- WBC 只写 Go2，`x5_fixed_hold` 只写 X5；
- X5 目标固定为 `[0, 0.3, 0.5, 0, 0, 0]`，夹爪固定为 `0.0`；
- WBC 使用 `--arm-observation-mode fixed_initial`；
- WBC 使用 `--require-arm-fixed-hold-safety`，实测臂状态失效会停 Go2；
- actor 的 6 维 arm joint position 使用固定训练姿态，6 维 arm velocity 和 arm
  action history 为零，6 维 arm command 固定，gripper command 为零；
- Rough 只允许经过严格时间、覆盖率、关键区和补全门控的 Unitree HeightMap；zero、
  last-valid 或直接点云都不能获得 motion permit；
- L1、writer 冲突、manifest/hash、arm、感知或 watchdog fault 均锁存，不自动恢复。

`--arm-observation-mode live`、`external_spacemouse` 和 WBC 自己写 X5 都会被生产入口
拒绝。

## 3. 一次性准备

### 3.1 Jetson 环境

生产使用系统 Python，不使用 Conda：

```bash
conda deactivate 2>/dev/null || true
cd ~/gx-real
uname -m
/usr/bin/python3 --version
/usr/bin/python3 -c "import onnxruntime; print(onnxruntime.__version__)"
```

`uname -m` 必须是 `aarch64`。不要在 x86 开发机执行真实 writer。

Rough 直接使用 Unitree onboard 高度图，不要求另建 GridMap workspace 或 elevation
mapper。先用统一只读入口完成机器盘点和 Unitree LiDAR/LIO 活性检查：

```bash
cd ~/gx-real
scripts/rough_real_ops.sh bootstrap
```

该命令不会安装 mapper、配置 CAN、释放 MCF 或创建 actuator writer。它直接检查
onboard deskew cloud、pose 和 HeightMap。也可单独重复 LIO 检查：

```bash
scripts/rough_real_ops.sh lio-check
```

通常不需要外部 launcher，直接验证 onboard 生产 topic：

```bash
scripts/rough_real_ops.sh perception-start
```

只有现场另有负责启动 Unitree 服务的可执行 wrapper 时，才设置
`GX_REAL_ROUGH_PERCEPTION_LAUNCHER`。生产 adapter 已按公开 IDL 的 x-major layout、
origin cell、米制单位和真机 bag 验证，不做假 topic 重命名。

### 3.2 LiDAR 校准

Rough 首次上机、传感器/支架拆装、固件或 mapper 配置变化后，必须完整执行
[LiDAR 安装、外参与验收指南](lidar_calibration.md)。尤其确认：

- `T_base_lidar` 方向为 `p_base = T_base_lidar * p_lidar`；
- `/utlidar/robot_pose` 是 `base_link` 原点在 `odom` 下的 pose，不是 LiDAR pose；
- map 与 pose header frame 相同；
- 0.10 m 台阶的前后/左右符号、yaw ±90°、x/y 展开顺序均通过；
- `perception_contract.yaml` 仍保持 `UNVERIFIED`，直到目标硬件证据被独立复核。

生产 HeightMap 路径不读取 WBC 的 `--height-scan-extrinsic`；原生服务必须已经正确
处理 LiDAR 到机身的几何。

首次完整校准使用 `rough_real_ops.sh calibration-init/calibration-capture/status`。
此阶段 MCF 必须保持活动以维持标准站立，并增加独立物理支撑；校准命令只读检查
MotionSwitcher 状态，不释放 MCF，也不允许 Go2/X5 writer。不要在校准阶段运行
`preflight`、`arm` 或 `legs`。完整场景命令见 LiDAR 校准指南第 4 节。

### 3.3 策略包离线检查

Rough：

```bash
/usr/bin/python3 scripts/height_scan/check_policy_height_scan_contract.py \
  --policy-kind rough \
  --policy policies/rough/current/policy.onnx \
  --env-yaml policies/rough/current/env.yaml \
  --contract policies/rough/current/height_scan_contract.yaml
```

该命令同时检查 260D/12D shape、187D live height、精确采样网格合同、固定 arm 训练
配置、10 cm 台阶敏感性和 Torch/ONNX reference parity。Flat 对应命令为：

```bash
/usr/bin/python3 scripts/height_scan/check_policy_height_scan_contract.py \
  --policy-kind flat \
  --policy policies/policy.onnx \
  --env-yaml policies/env.yaml
```

## 4. 每次上机 preflight

先保证所有 actuator 禁能、Go2 吊起或位于安全架、X5 接近固定姿态且周围无人。不要
同时运行 ARX 示例、SpaceMouse arm writer 或 legacy WBC。

Rough：

```bash
cd ~/gx-real
export GX_REAL_OPERATOR_CONFIRM_ACTUATORS=YES
scripts/rough_real_ops.sh preflight \
  --network-iface eth0 \
  --can-if can0 \
  --check-joystick-motion
```

Flat 使用 `scripts/prepare_flat_run.sh`。preflight 会执行 ROS2 message/C++ 构建、系统
Python/import、CycloneDDS、CAN、Go2 topic、writer 冲突和 MCF 检查/释放；Rough 还
要求以下 topic 有消息且 type 正确：

```text
/utlidar/cloud_deskewed    sensor_msgs/msg/PointCloud2
/utlidar/imu               sensor_msgs/msg/Imu
/utlidar/height_map_array  unitree_go/msg/HeightMap
/utlidar/robot_pose        geometry_msgs/msg/PoseStamped
```

如果刚完成构建、只想重复硬件检查，可显式传 `--no-build`；第一次或代码变化后不能跳过
构建。`--allow-non-jetson`、`--no-can`、`--skip-go2-topics` 和
`--no-disable-sport-mode` 只允许离线诊断，不构成真机 preflight 通过证据。即使
preflight 已执行过释放，真机运行入口仍会再次使用 MotionSwitcher 检查/释放 MCF，
并在确认当前没有活动 motion mode 后才启动 Python 节点。

### 4.1 Rough 感知只读监视

在创建任何 actuator writer 前运行：

```bash
scripts/rough_real_ops.sh validate
```

在平地、台阶和机器人 yaw 变化测试中，必须持续看到：

```text
shape=187 ok=True fallback=False height_source=height_map_array
```

同时检查 `age_s <= 0.25`、map/pose frame 一致、原始 coverage 至少 0.55、补全后全局
coverage 至少 0.95、关键区至少 0.95、关键 sentinel 为 0。监视器成功只证明输入链路，
不授权硬件输出。

## 5. Rough 受控启动

本节只在发布门全部通过后执行。每个终端都先进入同一代码版本；统一入口会 source
匹配的 Rough policy 和 perception 环境，并重新执行只读感知门。

### 5.1 终端 A：先启动 X5 fixed-hold owner

```bash
cd ~/gx-real
export GX_REAL_OPERATOR_CONFIRM_ACTUATORS=YES
scripts/rough_real_ops.sh arm \
  --model X5 \
  --can-interface can0 \
  --safety-topic /safety/estop
```

节点此时只进入 `STANDBY/damping`，发布物理 `/arm/state` 和固定
`/arm/target_state`，不会自行驱动到目标。它等待 WBC 的 safety heartbeat，避免 X5
脱离 Go2 安全域独立运动。

若 X5 当前姿态距目标任一关节超过启动阈值，停止节点并按批准的无并发 writer
commissioning 流程把机械臂放到目标附近；不要同时启动另一个 CAN writer。

### 5.2 终端 B：再启动 Go2 Rough WBC

```bash
cd ~/gx-real
export GX_REAL_OPERATOR_CONFIRM_ACTUATORS=YES
scripts/rough_real_ops.sh legs \
  --device cpu \
  --pose_estimator none \
  --standup-mode internal \
  --base-command-source wireless_joystick \
  --joy-vx-axis ly \
  --joy-vx-sign 1 \
  --joy-vy-axis lx \
  --joy-vy-sign -1 \
  --joy-yaw-axis rx \
  --joy-yaw-sign -1 \
  --joy-deadzone 0.12 \
  --joy-max-vx 0.50 \
  --joy-max-vy 0.0 \
  --joy-max-yaw 0.0 \
  --arm-control-owner external_fixed_hold \
  --arm-observation-mode fixed_initial \
  --arm-state-topic /arm/state \
  --arm-target-topic /arm/target_state \
  --safety-topic /safety/estop \
  --require-arm-fixed-hold-safety \
  --gripper-cmd 0.0 \
  --leg-kp 200 \
  --leg-kd 10
```

不要传另一类 policy/manifest，也不要覆盖 `--arm_pose`。入口从签名部署配置和
`env.yaml` 读取精确训练姿态，并在加载时验证六个 arm command range 均为 `[0, 0]`、
action padding 为零和 gripper 固定。

该入口会先运行 MCF 释放工具；若释放无法确认，WBC 不会启动。MCF 释放成功后，节点
在收到第一帧有效 LowState 时立即以当前腿关节角连续发送 Passive 命令
（`Kp=0, Kd=3`），因此等待 R1 期间没有低层控制空挡。此阶段不要求 Rough
HeightMap 已经取得 motion permit；地图只在 L2/策略切换时参与检查。

启动日志必须明确说明：actor arm observation 固定整个进程生命周期；arm topic 只用于
physical fixed-hold safety。用 `--arm-observation-mode live` 启动会被拒绝。

### 5.3 终端 C：使能物理固定姿态

确认 A/B 都无 fault、终端 B 已持续发布健康 `/safety/heartbeat` 后：

```bash
cd ~/gx-real
export GX_REAL_NETWORK_IFACE=eth0
source scripts/setup_env.sh
ros2 topic pub --once \
  /arm/fixed_hold/enable std_msgs/msg/Bool "{data: true}"
```

X5 应以受限速度进入并保持 `[0, 0.3, 0.5, 0, 0, 0]`。在 Go2 进入 policy 前确认：

- fixed-hold producer 正确，state/target 持续 fresh；
- 实测跟踪误差进入部署合同范围；
- `/safety/estop` 未锁存；
- Rough HeightMap 已连续至少 5 帧有效；
- actor fixed observation 日志未因真实 X5 运动而变化。

真实 X5 数值发生变化是正常的物理跟踪过程，但只能影响 safety ready/fault，不能影响
actor 的 arm observation。

### 5.4 Flat 的差异

Flat 使用以下匹配入口：

```text
scripts/run_x5_fixed_hold_flat.sh
scripts/run_leg12_flat_real.sh
```

其启动顺序、固定 arm 输入和安全门相同，但不启动 Rough HeightMap provider；
observation `[66:253]` 必须是精确零。禁止 Flat arm node 与 Rough WBC 混用。

## 6. 手柄与分阶段放行

- `R1`：执行内部 FixStand；最终腿目标就是策略的 ready/action offset，不调用 MCF
  或外部起身控制器，也不把当前站姿动态改写为策略 offset；
- `L2`：检查当前 FixStand 跟踪误差，通过后直接进入 rollout，不再执行额外的 1.5 s
  二次姿态对齐；
- `R2`：正常停止 policy，并回到内部 FixStand 保持；若尚未按 R1，则回到 Passive；
- `L1`：软件急停，锁存 ESTOP 并通知 X5 damping；
- 摇杆：只生成底盘速度，不控制 X5。

首次硬件试验按以下顺序推进，每一级都保存日志并独立复核后才能进入下一级：

1. 无 actuator 的策略/地图离线回放；
2. Go2/X5 架空，zero command，短时 shadow；
3. X5 fixed-hold 单独进入目标，Go2 不 rollout；
4. Go2 零速度站立，限制时长；
5. 平地低速、限时、限距；
6. 已标定的低风险台阶/粗糙地形。

现场必须有物理急停和独立安全人员。不要为了收日志延迟停机。

## 7. 正常停止与急停

正常停止：

1. 摇杆归零并按 `R2`；
2. 关闭 X5 fixed-hold：

   ```bash
   ros2 topic pub --once \
     /arm/fixed_hold/enable std_msgs/msg/Bool "{data: false}"
   ```

3. 确认 X5 已进入 damping；
4. Ctrl-C 终端 B（Go2 WBC）；
5. Ctrl-C 终端 A（X5 owner）；
6. 检查没有残留 writer：

   ```bash
   pgrep -af "run_wbc|run_leg12|run_x5_fixed_hold|run_spacemouse_arm|arx5"
   ```

异常时立即按 L1 或物理急停。fixed-hold feedback、tracking、heartbeat 或 CAN fault 会由
X5 节点发布 `/safety/estop=true`，WBC 应停止 Go2；该 fault 不允许自动清除后继续走。
查明原因后，完整停止两个 writer 并从 preflight 重新开始。

## 8. Rough 地图快速诊断

生产采样合同为：

```text
x_map = x_robot + cos(yaw) * x_base - sin(yaw) * y_base
y_map = y_robot + sin(yaw) * x_base + cos(yaw) * y_base
obs    = clip(base_z - elevation(x_map, y_map) - 0.5, -1, 1)
```

187 点使用发布包内精确 `grid_xy`：17 个 x 位置先变化，11 个 y 行后变化。Unitree
HeightMap 使用 `data[width * iy + ix]`，`origin` 是 cell `[0,0]` 的世界坐标。
实测高度不平滑；短期 world cache 只复用同一世界位置，局部平面只补机身遮挡区和
非关键区，前向中央关键未知保持 fail-closed。

常见拒绝原因：

| 现象/日志 | 首先检查 |
| --- | --- |
| `frame_mismatch` | map/pose header frame；pose 是否真的是 base_link 原点 |
| `invalid_pose` | 四元数是否 finite、非零；定位是否正确归一化 |
| `pose_map_skew` | 是否使用真实采样 stamp；同步/deskew 队列 |
| `stale_*` | topic 频率、DDS、CPU 负载和传感器时间 |
| coverage/critical sentinel | 外参、self-filter、地图范围、遮挡和 mapper unknown cell |
| 台阶左右/前后颠倒 | `T_base_lidar` 方向、REP-103 轴、HeightMap x-major 与 flatten 顺序 |
| yaw 后地形漂移 | localization pose 含义、外参 yaw、map frame |
| 平地整体偏高/偏低 | base_link z 原点、外参 z、mapper elevation 基准 |

Rough 感知失效时不能改成 zero/last-valid 继续走。先停止 writer，使用监视器和对应
rosbag 复现，再修正感知链。

## 9. 运行记录

每次硬件运行至少保存：

- source commit、工作树状态和 Flat/Rough artifact manifest；
- Jetson/ROS/Python/ONNX Runtime/Unitree SDK/ARX5 SDK 版本；
- LiDAR 型号/固件、外参/self-filter/mapper 配置 SHA；
- WBC、fixed-hold、感知和 preflight 完整日志；
- map/pose rate、age/skew、coverage 分布和 fault；
- X5 feedback/tracking/lease fault；
- 操作者、复核人、场地、阶段、最大命令、时长和停止原因。

任何版本或哈希与已发布合同不一致，都不应把该次运行标记为生产通过。

## 10. 禁止事项

- 不使用无类型的 `scripts/run_leg12_real.sh`；
- 不向生产 WBC 传 `live` arm observation、`external_spacemouse` 或 `wbc` arm owner；
- 不同时运行 fixed-hold、SpaceMouse、ARX 示例或其他 X5 CAN writer；
- 不让真实 `/arm/state` 进入 actor；
- 不在非 dry-run 允许 missing CAN；
- 不让 Rough 以 zero、last-valid 或直接点云取得 motion permit；
- 不把 `--height-scan-extrinsic` 当作原生 HeightMap 外参修复；
- 不通过降低 coverage、放宽 timeout 或修改 release 字样绕过问题；
- 不在 x86 开发机或未复核的脏工作树上执行真实部署。
