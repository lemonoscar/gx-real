# gx-real 上机使用指南

这份文档是当前 `gx-real` 真机主流程的完整操作指南，面向 `Go2 + X5/ARX5 + SpaceMouse`。默认部署主机是狗身上的 Jetson Orin NX，仓库路径按 `~/gx-real` 书写。

当前主线是分离控制：

- WBC 只控制 Go2 腿部，入口是 `scripts/run_leg12_real.sh`。
- X5/ARX5 只由独立 SpaceMouse Arm 节点控制，入口是 `scripts/run_spacemouse_arm.sh`。
- WBC 不打开 `can0`，只订阅 `/arm/state` 和 `/arm/target_state` 填 policy observation。
- SpaceMouse Arm 节点是默认唯一 X5 CAN 写进程，会打开 `can0` 并直接调用 ARX5 Cartesian controller。
- `L1` 急停由 WBC 发布 `/safety/estop`，SpaceMouse Arm 节点收到后把 X5 切到 damping，并阻止后续 X5 target 发送。

相关实现位置：

- WBC 启动脚本：`real-wbc/scripts/run_wbc_leg12.py`
- WBC 节点：`real-wbc/modules/wbc_node_leg12_arm_passthrough.py`
- SpaceMouse Arm 启动脚本：`real-wbc/scripts/run_spacemouse_arm.py`
- SpaceMouse Arm 节点：`real-wbc/modules/spacemouse_arm_node.py`
- CAN owner lock：`real-wbc/modules/can_owner_lock.py`
- Arm observation cache：`real-wbc/modules/arm_observation.py`

## 1. 硬件和安全前提

必需硬件：

- Unitree Go2。
- 狗身上的 Jetson Orin NX。
- X5/ARX5 机械臂和稳定 24V 供电。
- USB-CAN 转接器，默认接口名是 `can0`。
- Go2 手柄。
- 3Dconnexion SpaceMouse。

上机安全要求：

- 机械臂和狗周围必须留出安全空间。
- 操作者必须能随时按到 Go2 手柄 `L1` 和硬件急停。
- 第一次验证时 `--cmd-vx` 必须从 `0.0` 或 `0.1` 开始，不要直接跑高速。
- 不允许同时运行两个 X5 写控制进程。默认只允许 `scripts/run_spacemouse_arm.sh` 打开 `can0`。
- 不允许在真机运动中使用 `--allow-missing-can`、未接入 lock 的 ARX5 示例，或 WBC legacy arm writer。

## 2. 初次配置

以下步骤只需要在一台新的 Jetson 或新系统上做一次。执行前先退出 conda，真机默认使用系统 `/usr/bin/python3`：

```bash
conda deactivate
cd ~/gx-real
```

确认这是机器人端 Jetson：

```bash
uname -m
cat /proc/device-tree/model 2>/dev/null || true
which python3
/usr/bin/python3 --version
```

预期：

- `uname -m` 是 `aarch64`。
- 上机脚本使用 `/usr/bin/python3`，不是 conda 的 Python。

### 2.1 准备 policy 文件

确认 policy 和配置存在：

```bash
cd ~/gx-real
ls policies/policy.onnx
ls policies/env.yaml
```

`scripts/setup_env.sh` 默认读取：

```text
GX_REAL_POLICY_PATH=~/gx-real/policies/policy.onnx
```

如果 policy 放在其他位置，先导出环境变量：

```bash
export GX_REAL_POLICY_PATH=/abs/path/to/policy.onnx
```

### 2.2 安装/检查系统 Python 推理依赖

```bash
/usr/bin/python3 -c "import onnxruntime; print('onnxruntime ok')"
```

如果失败，需要给 Jetson 的系统 Python 安装匹配 JetPack/Ubuntu/aarch64 的 ONNX Runtime。不要只安装到 conda 环境。

### 2.3 安装 ARX5 Python 接口

```bash
cd ~/gx-real/arx5-sdk
source /opt/ros/foxy/setup.bash
/usr/bin/python3 -m pip install --user --no-build-isolation .
```

如果系统是 Humble：

```bash
source /opt/ros/humble/setup.bash
```

检查：

```bash
cd ~/gx-real
source scripts/setup_env.sh
/usr/bin/python3 -c "import arx5_interface; print('arx5 ok')"
```

### 2.4 编译 Unitree ROS2 消息包

```bash
cd ~/gx-real/unitree_ros2/cyclonedds_ws
source /opt/ros/foxy/setup.bash
colcon build
```

至少需要 `unitree_go`、`unitree_api`、`unitree_hg` 可用。

### 2.5 编译本仓库 robot_state 消息包

`/arm/state`、`/arm/target_state`、`/teleop/*` 的 ROS2 消息都在这里：

```bash
cd ~/gx-real/real-wbc/ros2
source /opt/ros/foxy/setup.bash
colcon build --packages-select robot_state
```

### 2.6 安装 SpaceMouse 依赖

```bash
sudo apt install libspnav-dev spacenavd
sudo systemctl enable spacenavd.service
sudo systemctl start spacenavd.service
/usr/bin/python3 -m pip install --user atomics
/usr/bin/python3 -m pip install --user https://github.com/cheng-chi/spnav/archive/c1c938ebe3cc542db4685e0d13850ff1abfdb943.tar.gz
```

不要安装 PyPI 默认的 `spnav==0.9`。如果看到 `PyCObject_AsVoidPtr`，先卸载再装上面的固定版本：

```bash
/usr/bin/python3 -m pip uninstall -y spnav
```

### 2.7 初次环境总检查

```bash
cd ~/gx-real
source scripts/setup_env.sh
scripts/check_env.sh
scripts/check_env.sh --spacemouse
```

通过时应看到：

```text
[gx-real] environment ready
[gx-real] python imports OK
[gx-real] spacemouse imports OK
```

## 3. 每次上机前检查

每次真机运行前都按本节执行。

### 3.1 进入仓库并加载环境

```bash
conda deactivate
cd ~/gx-real
git pull
source scripts/setup_env.sh
```

检查当前环境：

```bash
echo "${GX_REAL_ROOT}"
echo "${GX_REAL_POLICY_PATH}"
echo "${GX_REAL_PYTHON_BIN}"
scripts/check_env.sh --spacemouse
```

预期 `GX_REAL_PYTHON_BIN=/usr/bin/python3`。

### 3.2 检查 Go2 网络

确认连接 Go2 的网卡名，常见是 `eth0`：

```bash
ip a
ip route
```

如果 ROS2 topic 已经通，应该能看到 Go2 topic：

```bash
ros2 topic list | sort
```

至少应能看到低层状态相关 topic，例如 `lowstate`。

### 3.3 配置 X5 CAN

先看 `can0` 是否已经存在：

```bash
ip -details link show can0
```

如果不存在或不是 `UP`，执行：

```bash
scripts/setup_arx_can.sh
ip -details link show can0
```

如果自动检测到多个 USB-CAN 设备，显式指定设备：

```bash
scripts/setup_arx_can.sh /dev/serial/by-id/usb-XXXX can0 8
```

### 3.4 关闭 Go2 sport mode

Go2 原厂高层控制和低层 `lowcmd` 不能同时抢控制权。上机前关闭 sport mode：

```bash
scripts/disable_sports_mode_go2.sh eth0
```

如果连接 Go2 的网卡不是 `eth0`，换成实际网卡名。

### 3.5 确认没有其他 X5 写控制进程

禁止同时运行这些进程：

- `arx5-sdk/python/examples/spacemouse_teleop.py`
- `scripts/run_arm_spacemouse_test.sh`
- `real-wbc/modules/wbc_node.py`
- WBC `--arm-control-owner wbc`
- 任何直接构造 ARX5 controller 写 `can0` 的脚本

可选检查：

```bash
pgrep -af "spacemouse_teleop|run_arm_spacemouse_test|run_spacemouse_arm|run_wbc"
```

当前仓库内的 `CanOwnerLock` 是协作式文件锁，会防止接入该 lock 的两个进程同时打开 `can0`。未接入 lock 的外部脚本仍可能绕过它，所以操作上必须人工确认。

## 4. 标准启动流程

推荐顺序是先启动 SpaceMouse Arm 节点，再启动 WBC。这样 WBC 进入 policy 前已经能收到 fresh `/arm/state`。

### 4.1 终端 A：启动 X5 SpaceMouse Arm 节点

```bash
cd ~/gx-real
source scripts/setup_env.sh
scripts/run_spacemouse_arm.sh \
  --can-interface can0 \
  --safety-topic /safety/estop \
  --sm-use-raw-frame true \
  --sm-pos-speed 0.03 \
  --sm-rot-speed 0.10 \
  --sm-deadzone 0.12 \
  --sm-watchdog-sec 0.25
```

启动后确认日志包含：

```text
Arm control owner: spacemouse_arm_node (can0)
SpaceMouse frame source: raw
safety estop topic: /safety/estop
```

另开小终端检查 topic：

```bash
source ~/gx-real/scripts/setup_env.sh
ros2 topic hz /arm/state
ros2 topic hz /arm/target_state
```

### 4.2 终端 B：启动 WBC

保守静态验证命令：

```bash
cd ~/gx-real
source scripts/setup_env.sh
scripts/run_leg12_real.sh \
  --device cpu \
  --pose_estimator none \
  --standup-mode internal \
  --base-command-source fixed \
  --cmd-vx 0.0 \
  --cmd-vy 0.0 \
  --cmd-yaw 0.0 \
  --arm-control-owner external_spacemouse \
  --arm-state-topic /arm/state \
  --arm-target-topic /arm/target_state \
  --safety-topic /safety/estop \
  --require-arm-state-for-rl \
  --gripper-cmd 0.0 \
  --leg-kp 200 \
  --leg-kd 10 \
  --arm_pose 0.0 0.5 0.3 0.0 0.0 0.0
```

确认日志包含：

```text
Arm control owner: external_spacemouse
WBC will only consume arm state from /arm/state and target from /arm/target_state
Press L1 for emergency stop
Deploy node ready
```

第一次动态验证把 `--cmd-vx` 改成 `0.1`。确认稳定后再逐步提高，例如：

```bash
--cmd-vx 0.3
```

不要第一次直接用高速命令。

### 4.3 手柄启动动作

看到 `Deploy node ready` 后：

1. 按 `R1`：启动 internal 起身。
2. 等狗稳定站住。
3. 按 `L2`：启动低层对齐，然后进入 RL rollout。
4. 如果要停止 policy，按 `R2`。
5. 任意异常，按 `L1`。

预期日志包括：

```text
Runtime targets | standup_mode=internal ...
Starting dog-only startup before rollout
Dog-only startup completed; starting rollout
Policy diag | ...
```

## 5. 操作方式

### 5.1 Go2 底盘和 policy

WBC 手柄按键：

- `R1`：启动 internal 起身。
- `L2`：起身后进入 policy；fixed 模式 rollout 中再次按 `L2` 会恢复配置的 `--cmd-vx/--cmd-vy/--cmd-yaw`。
- `R2`：停止 RL policy，清零底盘命令。
- `Y`：底盘 command 平滑切到 `0 0 0`；joystick 模式会 inhibit 到摇杆回中。
- `L1`：急停，发布 `/safety/estop` 并退出 WBC。
- `A/B/X/D-pad`：默认 no-op，不控制机械臂。

fixed 底盘命令由启动参数给出：

```bash
--base-command-source fixed
--cmd-vx 0.1
--cmd-vy 0.0
--cmd-yaw 0.0
```

无线摇杆底盘命令示例：

```bash
scripts/run_leg12_real.sh \
  --device cpu \
  --pose_estimator none \
  --standup-mode internal \
  --base-command-source wireless_joystick \
  --joy-vx-axis ly --joy-vx-sign -1 \
  --joy-vy-axis lx --joy-vy-sign -1 \
  --joy-yaw-axis rx --joy-yaw-sign -1 \
  --joy-deadzone 0.12 \
  --joy-max-vx 0.10 \
  --joy-max-vy 0.05 \
  --joy-max-yaw 0.20 \
  --arm-control-owner external_spacemouse \
  --require-arm-state-for-rl
```

### 5.2 X5 机械臂

机械臂只用 SpaceMouse 控制。WBC external 模式下不会下发 X5 command。

SpaceMouse Arm 节点参数：

- `--sm-use-raw-frame true`：使用 raw SpaceMouse 坐标。
- `--sm-pos-speed`：平移速度比例，第一次建议 `0.03`。
- `--sm-rot-speed`：旋转速度比例，第一次建议 `0.10`。
- `--sm-deadzone`：死区，第一次建议 `0.12`。
- `--sm-watchdog-sec`：SpaceMouse 样本 watchdog，默认 `0.25`。
- `--arm-command-frame`：发布 target 的 frame，可选 `base/world/arm_base`，默认 `base`。

### 5.3 X5 夹爪

SpaceMouse 左右按钮控制夹爪：

- button 0：`target_gripper` 增大。
- button 1：`target_gripper` 减小。

夹爪命令会被限制在硬件范围内：

```text
0.0 <= gripper_target <= robot_config.gripper_width
```

如果读不到硬件宽度，fallback 最大值是 `0.08`。

## 6. 急停行为

按下 Go2 手柄 `L1` 后：

1. WBC 在 `emergency_stop()` 中发布 `/safety/estop=True`。
2. 如果 WBC 处于 legacy `--arm-control-owner wbc`，WBC 自己也会对 X5 调 `set_to_damping()`。
3. WBC `exit(0)` 退出。
4. SpaceMouse Arm 节点收到 `/safety/estop=True` 后设置内部 `estopped=True`。
5. SpaceMouse Arm 节点调用 `controller.set_to_damping()`。
6. 后续 `_send_target()` 会被 `estopped` 阻断，不再发送 X5 target。

急停后不要继续操作恢复。正确做法：

1. 松开 SpaceMouse 和手柄。
2. 停止两个终端中的进程。
3. 检查狗姿态、机械臂姿态、X5 电源、CAN、日志。
4. 从上机前检查重新开始。

## 7. 验收流程

### 7.1 初次部署验收

执行：

```bash
cd ~/gx-real
source scripts/setup_env.sh
scripts/check_env.sh --spacemouse
python3 -m py_compile \
  real-wbc/modules/wbc_node_leg12_arm_passthrough.py \
  real-wbc/modules/spacemouse_arm_node.py \
  real-wbc/modules/can_owner_lock.py \
  real-wbc/scripts/run_wbc_leg12.py \
  real-wbc/scripts/run_spacemouse_arm.py
```

预期：

- Python import 检查通过。
- `py_compile` 无输出、退出码为 0。
- `can0` 可创建并 `UP`。
- `scripts/disable_sports_mode_go2.sh eth0` 能输出 sport mode 已关闭或 deactivate。

### 7.2 上机前验收

1. `scripts/check_env.sh --spacemouse` 通过。
2. `ip -details link show can0` 显示 `UP`。
3. `scripts/disable_sports_mode_go2.sh eth0` 已执行。
4. 没有其他 X5 写控制进程。
5. SpaceMouse Arm 节点已启动。
6. `/arm/state` 和 `/arm/target_state` 有频率。
7. WBC 日志显示 `Arm control owner: external_spacemouse`。

### 7.3 运动中验收

先静态：

- `--cmd-vx 0.0`
- 按 `R1` 起身。
- 稳定后按 `L2`。
- 看 `Policy diag` 中 `commands=[0.000 0.000 0.000]`，腿部目标和真实关节误差正常。

再低速：

- 改为 `--cmd-vx 0.1`。
- 重复 R1/L2。
- 狗应缓慢前进，姿态稳定。

最后逐步提高速度：

- `--cmd-vx 0.2`
- `--cmd-vx 0.3`

每次只改一个变量。

### 7.4 结束后验收

1. 先按 `R2` 停止 policy。
2. Ctrl-C WBC 终端。
3. Ctrl-C SpaceMouse Arm 终端。
4. 确认 X5 进入 damping 或无持续目标发送。
5. 保存日志目录，WBC 日志默认在 `logs/<timestamp>/run.log`。

## 8. 常见故障

### 8.1 WBC 启动后狗不动

`Deploy node ready` 只表示节点启动成功，还需要：

1. sport mode 已关闭。
2. 按 `R1`。
3. 等 internal 起身完成。
4. 按 `L2`。

如果看到：

```text
Refusing low-level rollout because sport_mode state has not been received
```

先检查 Go2 ROS2 状态链路。只有受控诊断时才考虑：

```bash
--allow-unknown-sport-mode
```

如果看到：

```text
Refusing low-level rollout while sport_mode is still active
```

重新执行：

```bash
scripts/disable_sports_mode_go2.sh eth0
```

### 8.2 WBC 拒绝进入 policy，因为 arm state stale

如果使用了 `--require-arm-state-for-rl`，WBC 会检查 fresh `/arm/state`。报错时先确认：

```bash
ros2 topic hz /arm/state
ros2 topic hz /arm/target_state
```

再确认 SpaceMouse Arm 节点没有报 CAN、ARX5 或 SpaceMouse 错误。

### 8.3 X5 不动

检查顺序：

1. `ip -details link show can0`
2. X5 24V 供电。
3. CAN 线和 USB-CAN 设备。
4. `arx5_interface` 是否能 import。
5. 是否已有其他进程占用 `can0`。
6. SpaceMouse Arm 节点是否拿到 CAN owner lock。

如果日志出现：

```text
CAN interface 'can0' is already owned by ...
```

说明已有接入 lock 的进程在写 X5。先停掉旧进程，再重新启动。

### 8.4 SpaceMouse 掉线或 reader 卡死

SpaceMouse Arm 节点会检查：

- reader 子进程 `is_alive()`。
- 共享样本 `receive_timestamp`。

如果样本超过 `--sm-watchdog-sec`，arm node 会打印 stale/watchdog 日志并对 X5 damping。

注意：当前 `spacemouse_shared_memory.py` 在没有新事件时仍会周期写入当前 timestamp。它可以覆盖 reader 卡死和进程死亡，但对“设备断开但 reader 仍循环发布旧非零 motion”的检测不完全。真机上如果怀疑设备断开，立即停止 arm node，不要继续操作。

### 8.5 `/arm/target_state` 的语义

`/arm/target_state.joint_target` 是 X5 controller 的 commanded joint target，不是测量关节角。

WBC observation 中：

- `arm_dof_pos` 来自 `/arm/state.joint_pos`。
- `arm_joint_command` 来自 `/arm/target_state.joint_target`。
- `gripper_command` 来自 `/arm/target_state.gripper_target`。

如果 target stale，`ArmObservationCache` 会 fallback 到 measured state 或启动 fallback pose。

## 9. 禁止和高风险操作

禁止：

- 同时运行 `scripts/run_spacemouse_arm.sh` 和 WBC `--arm-control-owner wbc`。
- 同时运行 ARX5 SDK 示例和 SpaceMouse Arm 节点。
- 在真机上用 `--allow-missing-can` 跑机械臂控制。
- L1 急停后不重启流程就继续操作。
- 未关闭 sport mode 就进入低层 rollout。
- 第一次上机直接使用高速 `--cmd-vx`。
- 在狗站不稳、X5 供电不稳、CAN 报错时继续跑 policy。

高风险：

- `--arm-command-frame world` 需要可靠 base/world pose，默认不要用。
- `--allow-unknown-sport-mode` 只能用于受控诊断。
- 修改 `--sm-pos-speed`、`--sm-rot-speed` 后必须先空载小幅验证。
- 修改 `--leg-kp`、`--leg-kd` 后必须从静态接管重新验收。

## 10. 面向操作者的简短 SOP

1. 确认场地安全，手能按到 `L1` 和硬件急停。
2. `conda deactivate`。
3. `cd ~/gx-real && git pull && source scripts/setup_env.sh`。
4. `scripts/check_env.sh --spacemouse`。
5. `scripts/setup_arx_can.sh`，确认 `can0` 为 `UP`。
6. `scripts/disable_sports_mode_go2.sh eth0`。
7. 确认没有其他 ARX5/X5 写控制进程。
8. 终端 A 启动 `scripts/run_spacemouse_arm.sh --can-interface can0 --safety-topic /safety/estop --sm-use-raw-frame true --sm-pos-speed 0.03 --sm-rot-speed 0.10 --sm-deadzone 0.12 --sm-watchdog-sec 0.25`。
9. 确认 `/arm/state` 和 `/arm/target_state` 有频率。
10. 终端 B 启动 `scripts/run_leg12_real.sh ... --arm-control-owner external_spacemouse --require-arm-state-for-rl --safety-topic /safety/estop --cmd-vx 0.0`。
11. 看到 `Deploy node ready` 后按 `R1`。
12. 等狗稳定站住。
13. 按 `L2` 进入 policy。
14. 静态稳定后，停止流程，把 `--cmd-vx` 从 `0.0` 改到 `0.1`，重新从第 8 步开始。
15. 运行中用 SpaceMouse 控制 X5，用 SpaceMouse 左右按钮控制夹爪。
16. 异常时立即按 `L1`。
17. 正常结束时先按 `R2`，再 Ctrl-C WBC，最后 Ctrl-C SpaceMouse Arm 节点。
